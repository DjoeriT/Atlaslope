## Should fix
1. **Hover is dropped, not replayed, when boundaries load after the pointer is already on a row** (src/map/createMap.ts:272-283). `hover()` filters ids against `boundaries`/`zones`; before they load, it returns an empty list and stores nothing, and nothing re-applies it afterwards. Low impact (the row must be hovered during the first load), but the same mechanism makes any hover lost if `dos.setData` (line 133) runs again, since feature state of a replaced source is cleared while `hovered` still says it is lit; the next identical hover is then skipped by the `key` equality check (line 281). Fix: keep `wantedHover` (the ids asked for) and re-run `hover(wantedHover)` after the data arrives; or reset `hovered = []` on setData.
2. **A pending reset leaks into the next navigation** (createMap.ts:379-386, 78, 224-232). `reset()` sets `resetCamera = true`, `framePending = true`. If boundaries are not loaded yet (or the learner opens another card before `render()` frames), `resetCamera` stays set and the next `focus()` frames with pitch 45 / north, throwing away the learner's tilt without their asking. Also `resetCamera` is only cleared at the end of `render()` when `framePending` is false, so the `'point'` branch is fine but a `render()` that returns early (`quizView`, line 187) keeps it. Fix: clear `resetCamera` in `focus(..., reframe=true)` and in `quiz()` entry; add a unit/UI case "reset, then navigate, tilt is kept".
